# CLAUDE.md

Инструкции для Claude Code и других ИИ-ассистентов в этом репозитории. Здесь
только правила и ссылки: файл грузится в каждую сессию целиком, поэтому
справочные данные живут в документации `docs/ru/`.

> Пиши лаконично на русском (комментарии, коммиты, ответы). Английский — только
> для технических идентификаторов, команд и путей.

## Что это

**CloudCLI** (upstream `siteboon/claudecodeui`) — веб-интерфейс к CLI-агентам
Claude Code, Cursor CLI и Codex. Это **форк холдинга GOLDJAXE**: единая удалённая
рабочая среда, доступ в основном с телефона по Tailscale. Ветка доработок —
`feat/goldjaxe-improvements`, основной репозиторий — remote `goldjaxe`, `origin` —
это upstream. Цели форка — `GOLDJAXE-FORK.md`.

**Боевой инстанс :3302** (`cloudcli-fork.service`) работает из `dist/` и
`dist-server/` **этой папки**, а сессия агента обычно идёт внутри него.

## Документация — сначала она

На вопрос об устройстве или поведении форка сначала смотри доку, а не
восстанавливай картину по коду: запрос → `docs/ru/index.md` → две-четыре нужные
страницы → ответ.

Страницу находят поиском: `rg '^description' docs/ru` — что о чём,
`rg -l '§N' docs/ru/fork` — где раздел реестра.

## Команды

```bash
npm run typecheck && npm run lint       # перед каждым коммитом
NODE_ENV=test npx vitest run [<file>]   # клиентские тесты; без NODE_ENV=test — сотни ложных падений
# серверные тесты — только через tsx и только в изолированном окружении:
H=$(mktemp -d); env -i PATH="$PATH" HOME="$H" DATABASE_PATH="$H/auth.db" \
  node_modules/.bin/tsx --tsconfig server/tsconfig.json --test "<path/to/*.test.ts>"
```

`npm install` — только с `--include=dev`: в среде выставлен
`NODE_ENV=production`. Остальные команды — [`docs/ru/dev/development.md`](docs/ru/dev/development.md).

## Правила работы с кодом

- **Источник истины — код.** Дока отвечает «зачем» и «что нельзя», но имена
  флагов, полей и эндпоинтов сверяй с кодом, не выдумывай.
- **Минимум конфликтов с upstream.** Контракты апстрима без нужды не меняй;
  правки локальны и с комментарием `GOLDJAXE fork (реестр §N)`.
- **Сборка здесь — это выкатка.** `npm run build` в этой папке сразу подменяет
  файлы под живым сервером, а рестарт службы обрывает сессию агента. Без
  согласования с владельцем собирай и проверяй в отдельном git worktree; слияние
  upstream — только там, сюда — `merge --ff-only` готового результата.
- **Тесты и тестовый инстанс — в изолированном окружении.** Сессия наследует env
  боевого инстанса (`DATABASE_PATH`, `SERVER_PORT`, `CLAUDE_CLI_PATH`): без
  `env -i` и своего `DATABASE_PATH` тест или сервер пишет в боевую
  `~/.cloudcli/auth.db`. Рабочие :3302 и :3301 не трогать.
- **Каталог моделей захардкожен** (`CLAUDE_PREDEFINED_MODELS`). `value` уходит в
  SDK как есть — алиас или ID, понятный Claude Code; у GPT шлюза — плюс суффикс
  effort ([модели](docs/ru/fork/models.md), [GPT](docs/ru/fork/gpt-gateway.md)).
- **Границы безопасности не ослаблять:**
  - вложение доходит до агента, только если лежит в `~/.cloudcli/assets` или в
    cwd рана (`isAllowedImageSourcePath`); не-картинки отдаются с
    `Content-Disposition: attachment`;
  - запись вне проекта запрещена, чтение — только в корнях на чтение
    ([файлы вне проекта](docs/ru/fork/file-viewer.md));
  - JWT в `?token=` для `<img>` и EventSource — штатно, не дыра.
- **Секреты.** В `user_settings` — только не-секретные UI-настройки. Новый
  секрет — через `sealSecret` (`server/shared/secret-box.ts`). Сейчас шифруется
  только ключ голоса, `user_credentials` хранятся открытым текстом: не обещай
  шифрования там, где его нет ([голос](docs/ru/fork/voice.md)).
- **Ключи, которыми владеет апстрим (`user_preferences`), в наш allowlist
  `userSettingsSync` не добавлять** — два механизма на один ключ откатывают выбор
  пользователя ([настройки](docs/ru/fork/user-settings.md)).
- **Портальные меню и тач.** Меню через `createPortal`, которое закрывается
  `document`-listener'ом на `pointerdown`, обязано гасить всплытие на пунктах
  (`stopPropagation`), а listener — оставаться bubble-фазным, иначе на тач выбор
  не срабатывает (комментарий в `ChatComposer.tsx`).
- **Проверяй себя перед коммитом:** typecheck и lint — 0 ошибок, новых
  предупреждений не добавлять; при правках сервера — сборка (в worktree, см.
  выше) и профильные `node:test`; новая серверная логика — тест рядом
  (`server/**/tests/*.test.ts`); UI и тач — проверка в браузере на мобильном
  вьюпорте на изолированном инстансе.

## Реестр правок — тем же коммитом

🔴 Любое изменение кода форка (`src/`, `server/`), моделей, инфраструктуры или
деплоя → запись в реестре **в том же коммите**. Реестр — оглавление
[`docs/ru/fork-changes.md`](docs/ru/fork-changes.md) и страницы
`docs/ru/fork/<тема>.md`: правка — раздел «§N» на странице своей темы (новая
тема — новая страница), номер — в указатель оглавления; порядок — его
«Регламент ведения». По каждой правке: что и зачем, ключевые файлы, риск
конфликта с upstream (🟢/🟡/🔴), статус PR. Снятую или поглощённую upstream
правку не удаляй — меняй ей статус.

Зачем: форк живёт рядом с активным upstream, и при новой версии оригинала реестр —
единственный способ без расследования понять, что мы меняли и как сливать.

## Документация — тем же изменением

- Изменил поведение — обнови страницу темы в `docs/ru/` и её `updated`.
- Новая модель, флаг, эндпоинт или механизм → реестр плюс
  [`docs/ru/dev/architecture.md`](docs/ru/dev/architecture.md).
- Крупная доработка → страница в реестре плюс строка в его «Правках по темам» и
  в `GOLDJAXE-FORK.md`.
- Новая страница → строка в `docs/ru/index.md`. Одна тема — одна страница,
  больше ~300 строк — дробить; формат — [правила ведения](docs/ru/index.md#правила-ведения).
- `docs/upstream/` — зеркало официальной доки (EN): правим осторожно, наши
  пометки — отдельными блоками или файлами.
- **В этот файл справочные данные не дописывать** — только правило и ссылку на
  страницу документации.

## Git

- Коммиты по-русски, префиксы `feat/fix/docs/refactor/chore`. Последняя строка
  сообщения — `Co-Authored-By: Claude Opus 4.8 (1M context)
  <noreply@anthropic.com>`. PR в апстрим `siteboon/claudecodeui` — по политике
  гибрид «форк+PR».
- **🔴 Коммит и пуш — сами, после каждого значимого изменения, без отдельной
  просьбы.** Значимое — законченная правка кода, конфигурации или документации,
  которая заслуживает отдельной строки в истории. Промежуточные шаги и
  эксперименты не коммитятся. Порядок:
  1. Проверки по правилу выше. Упали — не коммить, а сообщи владельцу, что
     сломано.
  2. Одна логическая правка — один коммит, реестр и документация — в нём же.
     Чужие незакоммиченные изменения в дереве не смешивай со своими: раздели по
     коммитам или оставь как есть и скажи владельцу.
  3. Пуш — в основной репозиторий: `git push goldjaxe feat/goldjaxe-improvements`
     (ssh — с префиксом keychain из глобальных правил). В `origin` — это upstream
     siteboon — не пушить никогда; `--force` — только по прямой просьбе.
  4. GitHub-зеркало (`git publish`) — только по просьбе владельца: из него
     обновляются коллеги.
  5. Выкатка (сборка в этой папке + рестарт службы) по-прежнему согласуется
     отдельно: пуш её не подразумевает.

## Завершение работы в отдельном рабочем дереве (worktree)

- Дополнительное рабочее дерево временное. После принятия и слияния доработки в целевую ветку проекта (`dev`, `main`, `master` или явно согласованную другую) в той же сессии останови его локальный демонстрационный сервер и удали каталог дерева. Не оставляй завершённые копии рядом с основным проектом.
- Перед удалением обнови ссылки нужного удалённого репозитория и проверь, что `HEAD` дерева входит в целевую ветку: `git merge-base --is-ancestor <HEAD-дерева> <целевая-ветка>`. При squash или rebase отдельно подтверди сохранность всех изменений. Одного имени задачи, наличия ветки на сервере или сообщения о слиянии недостаточно.
- Проверь `git status --porcelain=v1 --untracked-files=all`, а также игнорируемые файлы: настройки, локальные базы, выгрузки и результаты работы могут не попадать в Git. Уникальные нужные данные сначала сохрани вне удаляемого дерева, секреты не добавляй в репозиторий. Невлитые коммиты, незакоммиченные изменения и спорные копии оставляй с указанием причины.
- Убедись, что дерево не используется другой активной сессией или задачей. Демонстрационный сервер останавливай только по проверенному PID, рабочему каталогу и порту, без широкого `pkill -f`. Общие службы и серверы других проектов не трогай. Проверь, что процесс завершён и его порт больше не занят этим сервером.
- Выйди из удаляемого каталога и выполни `git -C <основной-проект> worktree remove <путь>`. Не применяй `--force`, `git clean -fdx`, `reset --hard` или `rm -rf` для обхода проверки. Отдельный клон проверяй как самостоятельный репозиторий, а не как worktree. Ветки без отдельного запроса не удаляй.
- После уборки проверь `git worktree list` и отсутствие удалённого каталога. Устаревшие записи отсутствующих деревьев сначала просмотри через `git worktree prune --dry-run`; не удаляй записи временно недоступных или заблокированных деревьев. В итоговом ответе укажи удалённые деревья, остановленные серверы и то, что сохранено с причиной.
