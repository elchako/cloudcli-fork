# Обновление upstream v1.37.11 (2026-11-27)

> Раздел реестра §28. Часть [реестра правок форка](../fork-changes.md).

## §28 Объём и решения

- **Слой:** клиент и сервер · **Столкновение:** 🟡 (пины, композер, авторизация, SQL) · **PR:** отдельный PR не открыт.
- Проба — от `b5c23a22`, итоговое слияние — от `f7bb44d1`. Предыдущий тег —
  `v1.37.9` (`f86543fa`). В `merge --no-ff --no-commit` с `v1.37.11`
  (`de4c768b`) входит и `v1.37.10`; чистый тег проверен отдельно.
- Взяты запоминание режима разрешений на сеанс и последний выбор по проекту,
  режим рана и статус в Agent API, non-blocking загрузка шрифтов, исправления
  размеров таблиц/композера и перетаскивания редактора, обновление Codex CLI из
  настроек, рендереры инструментов включённых плагинов. Вызовы обновления CLI и
  внешние плагины не запускались.

## Пересечения с форком

В пробе разрешены 15 конфликтных файлов. Итоговое слияние поверх `f7bb44d1`
включает и компактную панель: выделение открытого разговора по маршруту
совмещено с кнопками закрепления в обоих видах поиска. Строки без значков,
подтверждения и мобильное меню «Инструменты» сохранены.

| Участок | Решение |
|---|---|
| `server/index.ts` | Общее чтение тела перенесено за JWT по upstream; в группах с собственной проверкой credentials — лимит 1 МБ. Для `protected-data` сохранён собственный парсер 400 КиБ после `validateApiKey` и `authenticateToken`; для `speech-summary` — JSON после JWT. Принято сравнение API- и Browser MCP-ключей с постоянным временем. |
| `assets.routes.ts`, `upload.middleware.ts` | Приняты безопасные коды ошибок и `X-Upload-Request-ID`. Сохранены выдача не-картинок и SVG как `attachment`, допуски и лимиты `/images` и `/files`, проверка владельца до записи и при регистрации Mail. Диагностика не логирует тела и имена файлов. |
| `ChatComposer`, `useChatComposerState` | Именованный отказ по типу, пустому файлу, размеру и количеству; композер ограничен 5 файлами, размер совпадает с `/files` (10 МБ). Вложения и отказы разложены по `draftScope`; новый ввод не стирается после загрузки. Сохранены замок, плашка защищённого набора, навигатор, микрофон и опции метрик. |
| `sessions.db.ts`, поиск, `SidebarContent` | `sessions.isPinned` остаётся единственным источником. Отдельная per-user таблица, API и раздел upstream не подключены: иначе существующие пины и порядок в дереве могли бы разойтись. Кнопки в поиске по названию и тексту используют прежний `POST …/toggle-pin`; флаг переносится при замене дубля индексатора. [§9.1](pins.md) описывает прежний порядок и область действия. |
| `provider-models.service`, `useChatProviderState` | Хранение `permission_mode` принято без переноса старых UI-настроек. Для нового чата полное отключение проверок не наследуется лишь из проектной истории; сохраняется явный прежний выбор пользователя. В рабочем чате восстановление идёт по сеансу. Каталог шлюза, исходные ID, правила effort/930k и Antigravity оставлены форковыми. |
| `server/modules/agent/agent.routes.ts` | Новый маршрут статуса проверяет действующий ключ Agent API до обращения к сеансам во всех режимах. Платформенный контракт остальных маршрутов не меняется. Регрессии в `server/modules/agent/tests/agent.routes.test.ts` проверяют отказ без ключа и с неактивным ключом, а также ответ с действующим ключом. |

В автослитых файлах проверены привязка закрытой доставки к текущему WS/ходу,
граница вложений `assets`/cwd, `userSettingsSync`, предки fork вне страницы,
вызовы `clearSession`/`expireAuthSession`, обновление токена и отсутствие
дублирующей подсказки в футере. Миграции пинов не требуется.

## Проверки

- Итоговая ветка на чистых зависимостях: `npm run typecheck`, `npm run lint`
  и `npm run build` успешны. Lint: 155 предупреждений против 156 у эталона,
  новых по файлу, правилу и сообщению нет. Предупреждения минификации CSS и
  размеров чанков известны по [§25](merge-v1.37.9.md).
- Клиент: 191 файл, 1476 тестов прошли (`NODE_ENV=test`, 2 процесса).
  Сервер: 1518 прошли, 2 пропуска. Основной набор — с отдельной сетью и БД;
  один файл с SSH-фикстурой — отдельно, со своим HOME/БД и тестовым OpenSSH на
  `127.0.0.1` (6/6). Рабочие SSH-ключи не использовались. Эталон v1.37.11:
  1262 клиентских и 1113 серверных тестов прошли, один серверный пропуск.
- Старая ошибка установки `EUSAGE` воспроизводилась и до обновления. В
  `package-lock.json` дописаны 11 недостающих записей, в том числе Jimp и
  `encoding`; 24 адреса зеркала заменены на npm Registry без изменения версий
  и контрольных сумм. Ни одна прежняя версия зависимости не поменялась.
  Чистый `npm ci --include=dev` на Node 24.13.0 / npm 11.6.2 установил 1801
  пакет и не изменил lock-файл. Проверены загрузка SQLite, `node-pty` и
  бинарник `ripgrep`; загрузка Electron и установка Git-хуков отключены.
- В пробе на стенде проверены `/health`, отказ без JWT у `protected-data`,
  отклонение пустого конверта и статус сводки. Chrome 1280×800: закрепление
  результата поиска и пин первым в REST-ленте.
- Финальный стенд `127.0.0.1:43302` поднят на синтетической БД со схемой
  v1.37.9. После миграции сохранились два сеанса, история, пин, связь с предком,
  полный заголовок, модель, effort и черновик. Новый `plan` сохраняется в
  сеансе, статус доступен с действующим ключом.
- Chrome 390×844, настоящий сервер: переключение вкладок и чатов тапом,
  разделитель, выделение чата в ленте и поиске, закрепление и открепление из
  поиска, дерево в «Проектах», принятие обычного вложения и сообщение об
  отказе для пустого файла. Скриншоты просмотрены, оба стенда остановлены.

## Статус

Проба и финальная проверка выполнялись в отдельных рабочих деревьях.
Выкатка на `:3302` не выполнялась. Боевые БД и службы не использовались.
Без запросов к реальным провайдерам, платным моделям, Mail, TTS и получателям
защищённых данных; обновление Codex CLI и Electron не запускались.
