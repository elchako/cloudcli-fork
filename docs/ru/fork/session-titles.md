# Сеансы: выделение активного и ИИ-названия

> Разделы реестра §4.6, §4.7, §4.8, §4.9, §4.9-бис. Часть [реестра правок форка](../fork-changes.md): номер § — постоянный адрес правки, по нему на эту страницу ссылаются код и коммиты.

## §4.6 Активный сеанс выделен явно + короткие ИИ-названия сеансов

- **Слой:** frontend + backend + БД · **Столкновение:** 🔴 · **PR:** кандидат
  (выделение — баг апстрима; ИИ-названия — наша фича, отдельным PR).
- **Симптом:** (1) выбранный сеанс отличался только `bg-primary/5` +
  `border-primary/20` — в тёмной теме неразличимо, непонятно какой сеанс открыт;
  (2) названием сеанса служил сырой первый запрос (`display` из
  `~/.claude/history.jsonl`), обрезанный по ширине строки, поэтому десяток
  сеансов подряд читался одинаково («Review this change for security…»).
- **Что сделано:**
  - **Выделение:** акцентная полоса 4px (`::before`), фон `bg-primary/15`,
    сплошная рамка + `ring-primary/40`, `font-semibold` у заголовка,
    `aria-current`. Обе ветки — десктопная и мобильная.
  - **Названия:** новый сервис `session-title.service.ts` сокращает первый
    запрос до «\<предмет\> — \<действие\>» (≤48 симв., первые два слова —
    проект/домен/файл/номер задачи, язык запроса сохраняется). Модель берётся из
    `ANTHROPIC_DEFAULT_HAIKU_MODEL`, доступ — по тем же `ANTHROPIC_BASE_URL` /
    `ANTHROPIC_AUTH_TOKEN` / `ANTHROPIC_API_KEY`, что и Claude Code.
  - **Подсказка:** полный исходный запрос хранится в новой колонке
    `sessions.full_title` и показывается в `title` при наведении.
  - **Перегенерация вручную:** кнопка-искра в строке сеанса (десктоп + мобила) →
    `POST /api/providers/sessions/:id/regenerate-title`. Индексация никогда не
    переписывает уже существующее имя, поэтому старые сеансы обновляются только
    этой кнопкой.
- **Отказоустойчивость (важно):** ни один сбой не оставляет сеанс без имени —
  при отсутствии ключей, ошибке шлюза, таймауте или ответе не в формате
  возвращается прежнее поведение (обрезанный сырой запрос). Отключается
  `CLOUDCLI_SESSION_TITLES=off`, модель переопределяется
  `CLOUDCLI_SESSION_TITLE_MODEL`.
- **Грабли, пойманные на живом стенде:**
  1. Шлюз холдинга (CLIProxyAPI) отвечает `400 clear_thinking_20251015 strategy
     requires thinking to be enabled` на обычный запрос → сервис делает один
     повтор с `thinking: {type:'enabled'}` (`max_tokens` > `budget_tokens`,
     `temperature` при этом слать нельзя).
  2. Первая индексация шлёт запрос на сеанс — при 121 сеансе шлюз рвал
     соединения (`fetch failed`) → запросы поставлены в последовательную очередь.
  3. Генерация не должна быть внутри синхронизации: `/api/projects` ждёт
     `synchronizeSessions()`, и ожидание сети там вешало список проектов
     (>2 мин). Теперь строка пишется с сырым именем сразу, а заголовок
     дописывается фоном (`scheduleTitle`) с проверкой, что имя не изменилось.
- **Файлы:** `server/modules/providers/services/session-title.service.ts` (новый),
  `server/modules/providers/tests/session-title.service.test.ts` (новый, 14 тестов),
  `server/modules/providers/list/claude/claude-session-synchronizer.provider.ts`,
  `server/modules/providers/services/sessions.service.ts`,
  `server/modules/providers/provider.routes.ts`,
  `server/modules/database/{schema,migrations}.ts`,
  `server/modules/database/repositories/sessions.db.ts`,
  `server/modules/projects/services/projects-with-sessions-fetch.service.ts`,
  `src/components/sidebar/**` (5 файлов: строка сеанса, список, проект, панель,
  контроллер), `src/utils/api.js`, `src/i18n/locales/{ru,en}/sidebar.json`.
- **Мерж-заметка:** колонка `full_title` добавляется миграцией
  `addSessionFullTitleColumn` (по образцу `addSessionModelColumn`) — при
  обновлении upstream следить за `migrations.ts` и за `SESSION_ROW_COLUMNS`.
  Переименование вручную (`renameSessionById`) теперь чистит `full_title`, иначе
  подсказка показывала бы устаревший текст.
- **Мерж-заметка (v1.37.2):** upstream добавил свою колонку `effort` той же
  миграционной механикой — в `migrations.ts` теперь **обе** функции
  (`addSessionFullTitleColumn` + `addSessionEffortColumn`), в
  `SESSION_ROW_COLUMNS` — **оба** поля. Конфликт был вида «обе стороны добавили
  своё в одну точку»: брать одну сторону нельзя, иначе тихо теряется колонка.
- **Мерж-заметка (v1.37.2) — строка сеанса переехала в меню.** Upstream заменил
  инлайн-кнопки в `SidebarSessionItem.tsx` на `ActionMenu` («три точки» +
  нижняя шторка на мобиле). Наша кнопка-искра больше не инлайн: она стала
  пунктом меню `regenerate-title` (иконка `Sparkles`, `loading:
  isRegeneratingTitle`) рядом с `rename`/`copy`/`delete`. Наше выделение
  активного сеанса (акцентная полоса, `ring`, `font-semibold`) сохранено и
  дополнено апстримовским `pr-11`, чтобы текст строки не заезжал под меню.
- **Мерж-заметка (v1.37.4) — заголовки от апстрима (#1258).** Имя для
  **отображения** новой сессии апстрим теперь берёт из транскрипта:
  `custom-title` (ручной `/rename` в CLI) > `ai-title` (свой заголовок Claude
  Code) > `last-prompt`, и только потом `history.jsonl`; функция
  переименована `extractSessionAiTitleFromEnd` → `extractSessionTitle`. Наш
  генератор работает как раньше — **источник** названия первый запрос
  (`extractFirstUserPrompt`), результат заменяет отображаемое имя, пока нет
  `full_title` и имя не меняли руками. Если все источники отображаемого имени
  пусты, у нас — первый запрос, у апстрима — «Untitled Claude Session»:
  апстримовский тест переименован и подогнан под нашу семантику
  (`claude-sessions.test.ts`, «falls back to the first prompt…»). Нюанс: ручной
  `/rename` из CLI, сделанный до первой индексации сеанса, наш генератор
  перезапишет — так было и до слияния.
- **Мерж-заметка (v1.37.4) — мультивыбор (#1404).** Строка сеанса стала
  чекбоксом в режиме выбора; объединено с нашим выделением: полоса/кольцо/
  `aria-current` + апстримовские `role="checkbox"`, `pr-2` при выборе и
  подсветка отмеченных; меню (с нашими «Закрепить»/«Перегенерировать») при
  выборе скрыто, как у апстрима.

## §4.7 Автозаголовок срабатывает и для новых сеансов (гонка индексации)

- **Слой:** backend · **Столкновение:** 🟡 · **PR:** вместе с 4.6.
- **Симптом:** у сеансов из истории заголовок появлялся, а у **новых** — нет:
  название оставалось сырым первым запросом. Кнопка перегенерации при этом
  работала, то есть сам сервис был исправен.
- **Причина — гонка.** Активный сеанс переиндексируется на *каждую* запись в
  файл беседы. Первый проход ставил фоновую генерацию (2–4 с), но следующая
  запись приходила раньше ответа модели, и на втором проходе срабатывал ранний
  выход «имя уже есть» (`custom_name` != пусто) — `rawPrompt` больше не
  возвращался, второго шанса не было никогда. У старых сеансов из истории
  повторной индексации нет, поэтому там всё работало.
- **Фикс:** признаком «уже озаглавлен» стал непустой `full_title`, а не сам факт
  наличия имени. Пока `full_title` пуст, имя считается сырым и генерация
  повторяется на следующем проходе. Чтобы это не превратилось в запрос на каждое
  нажатие клавиши, добавлен `titlesInFlight` — один активный запрос на сеанс.
  `scheduleTitle` перед записью перечитывает строку и пишет, только если имя
  всё ещё равно исходному запросу и `full_title` пуст → ручное переименование
  никогда не затирается.
- **Источник текста:** приоритет у `history.jsonl` (`buildLookupMap` берёт
  **первую** запись = первый запрос сеанса), сохранённое имя — запасной вариант,
  т.к. оно уже обрезано до 120 символов. Важно: `extractSessionAiTitleFromEnd`
  читает файл с конца и даёт *последний* запрос — на него опираться нельзя,
  иначе сеанс назовётся «да, спасибо!».
- **Файлы:** `server/modules/providers/list/claude/claude-session-synchronizer.provider.ts`,
  `server/modules/providers/tests/claude-session-titles.test.ts` (новый, 4 теста
  на настоящей БД + подменённый шлюз; тест «повторная индексация» падает на
  коде до фикса — проверено).

## §4.8 Промт заголовка — универсальный, срабатывает на любом запросе

- **Слой:** backend · **Столкновение:** 🟢 · **PR:** вместе с 4.6.
- **Симптом:** заголовок генерировался «через раз». Часть сеансов получала
  короткое имя, часть навсегда оставалась с обрезанным сырым запросом — при
  исправном сервисе и работающей кнопке перегенерации.
- **Причина — невыполнимое требование в промте.** Было жёстко: «Первые два
  слова **обязаны** называть предмет: проект, домен, сервис, номер задачи или
  файл». Если в первом запросе ничего этого нет (надиктованный голосом вопрос,
  обсуждение без привязки к задаче), модель упирается в требование, которое
  физически не может выполнить, и вместо заголовка отвечает пояснением. Дальше
  срабатывает отбраковка в `sanitizeModelTitle` (ответ длиннее `MAX_TITLE_LENGTH
  * 2` → `null`), и имя откатывается на сырой запрос. Отказ выглядел как «фича
  не работает», хотя запрос к модели проходил успешно.
- **Фикс:** требование к предмету стало **приоритетным списком**, а не
  обязанностью: (1) проект/домен/репозиторий/файл/номер задачи, если назван;
  (2) иначе — главная тема запроса. Добавлены: явное «заголовок обязателен
  всегда, не отказывайся и не проси уточнений»; разрешение обойтись без тире,
  когда действие не выражено; указание игнорировать оговорки и самоперебивания
  надиктованного текста.
- **Границы:** порог `MAX_TITLE_LENGTH` (48) не трогали — запросы короче него
  по-прежнему сами себе заголовок, модель не вызывается. Это не дефект.
- **Файлы:** `server/modules/providers/services/session-title.service.ts`
  (только константа `TITLE_SYSTEM_PROMPT`), тест-регрессия «titles a dictated
  prompt that names no project or issue key» в
  `server/modules/providers/tests/session-title.service.test.ts` — закрепляет
  формулировки промта, чтобы правку не откатили обратно при мерже.
- **Не сделано (осознанно):** генерация заголовков подключена **только к
  Claude** — `generateSessionTitle` импортируется в
  `claude-session-synchronizer.provider.ts` и больше нигде. Codex, Cursor и
  opencode её не имеют. Для Codex мало вызвать `scheduleTitle`: он берёт имя из
  `last_agent_message` (последний **ответ агента**), а не из первого запроса
  пользователя, — нужен отдельный парсер первого промта из
  `~/.codex/sessions/*.jsonl` и вынос `scheduleTitle` в общий хелпер. Отложено
  по решению CEO до проверки правки на Claude.

## §4.9 Автозаголовок: источник — первое сообщение, а не имя из истории

- **Слой:** backend + frontend · **Столкновение:** 🟡 · **PR:** вместе с 4.6.
- **Симптом:** автоматическое переименование «то работает, то нет». Ручная
  кнопка на десктопе отрабатывала, автоматика — почти никогда. На мобиле
  кнопки перегенерации не было вовсе, то есть починить имя с телефона было
  нечем.
- **Причина 1 — результат модели молча выбрасывался.** Защита от затирания
  ручного переименования сравнивала сохранённое имя с *промтом*:
  `custom_name === normalizeSessionName(prompt)`. После того как источником
  промта стал первый пост транскрипта (4.8), а имя по-прежнему приходило из
  `history.jsonl` или обрезанного слайса, эти строки перестали совпадать.
  Замер на живой БД: **39 из 40** сеансов → `stillUntitled === false` →
  сгенерированный заголовок отбрасывался. Модель вызывалась, деньги тратились,
  результат в БД не попадал.
- **Фикс 1:** сравнение переведено на `storedName` — имя, которое этот же
  проход только что записал (`parsed.sessionName`). Смысл защиты сохранён:
  если за время запроса имя изменилось (ручное переименование) или появился
  `full_title`, результат по-прежнему отбрасывается.
- **Причина 2 — для новых сеансов источником был последний запрос.** В ветке
  «сеанса ещё нет в БД» `rawPrompt` брался из `extractSessionAiTitleFromEnd`,
  который читает файл **с конца**. Заголовок строился по последней реплике —
  «да, спасибо!» вместо темы разговора.
- **Фикс 2:** источником стал `extractFirstUserPrompt` (первое сообщение);
  имя из `history.jsonl`/`ai-title` осталось запасным вариантом отображения.
- **Фикс 3 (UI):** в мобильное меню сеанса добавлен пункт перегенерации —
  раньше он был только в десктопном меню, хотя все нужные пропсы
  (`isRegeneratingTitle`, `onRegenerateSessionTitle`) в компоненте уже были.
- **Подпись кнопки** сокращена: «Перегенерировать название по первому запросу»
  → «Перегенерировать название» (ru + en), чтобы влезала в узкое меню.
- **Файлы:** `server/modules/providers/list/claude/claude-session-synchronizer.provider.ts`,
  `src/components/sidebar/view/subcomponents/SidebarSessionItem.tsx`,
  `src/i18n/locales/{ru,en}/sidebar.json`; тест-регрессия «stores the title when
  the display name differs from the prompt source» в
  `server/modules/providers/tests/claude-session-titles.test.ts` — **проверено,
  что он падает на коде до фикса**.
- **Известное ограничение:** служебные сеансы плагина security-review имя от
  модели не получают — их первый «промт» это ~20 КБ машинного JSON, а имя им
  ставит сам плагин (оно уже осмысленное). Отдельная задача по их группировке
  в реестре пока не заведена.

## §4.9-бис Метка прерывания вместо названия и «мёртвая» перегенерация (2026-10-17)

- **Слой:** backend · **Столкновение:** 🟢 (наши файлы) · **PR:** вместе с 4.6.
- **Симптом 1:** часть сеансов называется `[Request interrupted by user]`, кнопка
  перегенерации ничего не меняет. Замечено после выкатки v1.37.5: 2 из 74
  сеансов за день, за 10 дней до этого — ни одного.
- **Причина 1:** первый ход сеанса остановили до того, как CLI проверил промт
  (в логе `prompt_check: the turn was stopped before its prompt was checked`).
  Тогда в транскрипт пишется только метка `[Request interrupted by user]`, а
  настоящий запрос идёт следующим ходом. `extractFirstUserPrompt` брал метку
  как первый запрос; она короче порога в 48 символов, поэтому модель не
  вызывалась ни при индексации, ни по кнопке — имя навсегда оставалось меткой.
- **Фикс 1:** метка `[Request interrupted` добавлена к служебным префиксам
  (`MACHINERY_PREFIXES`), как уже сделано в ленте чата и поиске. Уже
  испорченные сеансы чинятся сами при следующей записи транскрипта (у них нет
  `full_title`, синхронизатор повторяет попытку) или кнопкой.
- **Симптом 2:** у сеанса с уже готовым ИИ-названием (например, «Graceful
  shutdown с очередью запросов») кнопка перегенерации «ничего не делает».
- **Причина 2:** запрос к модели шёл с `temperature: 0`, и на тот же промт она
  детерминированно отвечала тем же названием — запрос выполнялся, но имя не
  менялось.
- **Фикс 2:** `generateSessionTitle(prompt, { previousTitle })`: ручная
  перегенерация передаёт текущее имя, модели сообщается «прежний заголовок не
  подошёл», температура 1. Автоматическое название по-прежнему на
  `temperature: 0` (стабильное).
- **Не исправлено (не дефект кода):** английский термин в русском названии.
  «Graceful shutdown» модель оставляет при любой формулировке правила языка
  (проверено тремя вариантами промта на живом шлюзе); собственный `ai-title`
  Claude Code для того же сеанса — тоже «Graceful shutdown при релизах
  сервиса». Перегенерация теперь даёт другие формулировки, но термин может
  остаться.
- **Файлы:** `server/modules/providers/services/first-user-prompt.service.ts`,
  `server/modules/providers/services/session-title.service.ts`,
  `server/modules/providers/services/sessions.service.ts`; тесты
  `first-user-prompt.service.test.ts` (метка прерывания) и
  `session-title.service.test.ts` (перегенерация с прежним заголовком).
