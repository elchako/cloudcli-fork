# Как вливать upstream

> Разделы реестра §14.1, §6. Часть [реестра правок форка](../fork-changes.md): номер § — постоянный адрес правки, по нему на эту страницу ссылаются код и коммиты.

## Чужие дефекты, найденные при слияниях

> **Дефекты, найденные при слияниях (не наши).** Тест `conversation search
> streams title matches before transcript results` падал «то на одних версиях,
> то на других» (`v1.37.2`/`v1.37.3`, HEAD в [§15](file-viewer.md)). Причина не в коде, а в
> установке: в `node_modules` нет бинарника `@vscode/ripgrep/bin/rg`, его
> докачивает postinstall, и при сбое скачивания установка не падает ([§16.4](merge-v1.37.5.md)).
> На чистом `v1.37.4` `npm run typecheck` падает на собственном тесте апстрима
> (`recentConversationTitleSync.test.ts` без `backgroundSessionIds`) — у нас
> поправлено ([§14.4](merge-v1.37.4.md)), кандидат в PR.

## §14.1 Порядок, которым сливали (повторять так же)

1. `git fetch origin --tags`; два worktree **рядом** с основной папкой (не в
   `/tmp` — там tmpfs): слияние на ветке `merge/upstream-vX` и чистый тег
   апстрима — эталон, чтобы падение теста сразу сверять с апстримом.
   Основную папку не трогать: из неё работает боевой :3302 (CLAUDE.md).
2. `git merge --no-ff --no-commit vX` → конфликты → сверка автослитых общих
   файлов (`git diff vX -- <файл>` показывает ровно наши дельты поверх апстрима).
3. «Молчаливые» точки из реестра: подсказка в футере композера ([§4.3](composer.md)),
   микрофон в панели ([§4.12](voice.md)), безусловные `clearSession`/`expireAuthSession`
   ([§7](auth-session.md)), `dispatchEvent` в `storeAuthToken` и `token` в зависимостях
   `checkAuthStatus` ([§10](auth-session.md)).
4. typecheck, lint (сравнить набор предупреждений с эталоном), vitest
   (`NODE_ENV=test`), серверные тесты в изолированном env ([§14.5](merge-v1.37.4.md)), build.
5. Тестовый инстанс из worktree: `env -i`, свой `HOME` с синтетическими
   сеансами, свой `DATABASE_PATH`, `CLOUDCLI_SESSION_TITLES=off`,
   `CLOUDCLI_IMAGE_GEN=off`; браузер 390×844 и 1280×800.

## §6 Мерж-заметка: `docs/README.md` и корневой README

- **Слой:** доки · **Столкновение:** 🟢 (с v1.37.3 точки конфликта нет; следить
  только за нашим блоком в корневом `README.md`) · **PR:** нет.
- **v1.37.2 (upstream `0a2ad343`):** апстрим перенёс корневой `README.md` и его
  переводы в `docs/` и столкнулся с нашим оглавлением документации
  `docs/README.md` (добавлено `850290e1`). Конфликт «добавление/добавление»
  тогда развели так: `docs/README.md` — наше оглавление, апстримовский README
  лёг в `docs/upstream/README.md`, рядом с зеркалом остальной их документации.
- **v1.37.3 (upstream `125a293f`):** апстрим вернул README в корень
  (`docs/README.md` → `README.md`). При слиянии `3d708f25` это переименование
  молча удалило наше оглавление (79 строк): карту зеркала upstream, оговорки о
  качестве забора и план документации. Прежний текст этой заметки, который
  обещал конфликт в той же точке, с тех пор был неверен.
- **Восстановлено 31.10.2026.** Точка входа русской документации —
  [`docs/ru/index.md`](../index.md), карта зеркала и оговорки о качестве забора —
  [`docs/ru/upstream-mirror.md`](../upstream-mirror.md).
- **Что сейчас лежит в `docs/`:** от апстрима — переводы витрины
  `README.<язык>.md`, `architecture/`, `nginx-subpath-template.conf`; наше —
  `ru/` и `upstream/` (зеркало). Корневой `README.md` — апстримовский, с нашим
  блоком сверху (маркер `<!-- GOLDJAXE fork`).
- **На следующем слиянии:** блок форка в корневом `README.md` оставить сверху;
  свои файлы в корень `docs/` не класть — эту папку апстрим использует сам и
  может снова переименовать или удалить.
