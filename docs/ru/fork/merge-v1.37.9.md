# Обновление upstream v1.37.9 (2026-11-16)

> Раздел реестра §25. Часть [реестра правок форка](../fork-changes.md).

## §25 Объём и решения

- **Слой:** client + server + desktop-инфраструктура · **Столкновение:** 🟡 ·
  **PR:** слияние upstream в форк; отдельный PR не открыт.
- Тег `v1.37.9`, коммит `f86543fa`; предыдущая база — `v1.37.8` (`2053f3d7`).
  Полный merge выполнен в `merge/upstream-v1.37.9`, отдельный чистый worktree
  тега использован для сравнения. Основной каталог получает результат ff-only.
- **Исправления:** очередь отправляется по завершении ожидаемого рана, а не
  только очередным опросом; долгий scheduled-ран не блокирует другие сеансы;
  cleanup отправки относится к исходному чату; Escape в меню и переименовании
  не обрывает ответ; токены видны при вопросе агента; остановка фоновой задачи
  проверяется фактическим исчезновением из tracker; в побочный ответ не попадает
  reasoning, сообщения разделяются. Принят разбор OpenCode v2 config/JSONC.
- **Новые возможности:** дерево ответвлений в Projects, подгрузка старых
  Conversations при прокрутке, pinned-версии моделей в fallback; Linux `.deb`
  и турецкий перевод приняты, но desktop-пакет не собирался.
- Коммит `7943e285` не попал в список возможностей release notes, но входит
  в тег: `/clear` и кнопка сбрасывают контекст, сохраняя историю. Проверены
  сохранение истории и разделителя, ограничения занятой сессии; русские
  подписи добавлены. Это не автоматическая очистка и не удаление переписки.
- API-запуск допускает явный `unattended: false` для MCP-форм. Default остался
  unattended; запрос из UI по-прежнему требует решения человека.

## Пересечения с форком

Разрешены 11 конфликтных файлов; общие компоненты не заменялись целиком одной
стороной. Сохранены 365-дневная авторизация, корни чтения, границы assets/cwd,
настройки и шифрование секретов; новые дубли в `userSettingsSync` не добавлялись.

| Участок | Решение |
|---|---|
| `claude-models.provider.ts`, `claude-models.test.ts` | API — источник доступности. 13 pinned-версий upstream добавлены только в fallback и известные метаданные, не подмешиваются в успешный API-ответ. Сохранены прежние 1M/GPT/Kimi ID; плавающие алиасы форк не восстанавливает. Для точного native ID действуют defaults upstream, например Opus 5.5 — medium; старый `[1m]` сохраняет прежний high. |
| `claude-runtime.provider.ts`, `claude-runtime-hold.test.ts` | Проверен автослитый runtime: GPT effort/930k, Kimi, Antigravity с приоритетным settings.env, image MCP, вложения и Mail hooks сохранены; принята проверка stop-task upstream. |
| `useChatComposerState.ts` | Приняты scoped cleanup side question и edit state; сохранены более строгие проверки снимка текста и `setScopeAttachedFiles` для direct/queue/steer. Глобальное удаление файлов upstream не возвращено, повторное восстановление отказанной очереди исключено. Все новые upstream cleanup-тесты проходят. |
| `ChatComposer.tsx` | Кнопка сброса контекста принята; часы, дублирующая кнопка команд и справочная строка не возвращены. Микрофон, очередь диктовки и блокировка во время распознавания сохранены. |
| Sidebar и `useProjectsState.ts` | Дерево и infinite scroll объединены с пинами, полным запросом в подсказке, выделением, регенерацией и живыми названиями. Пин потомка поднимает семью, родитель остаётся перед потомком. Виртуализация проектов сохранена, данные страницы/offset не изменены. |
| `server/shared/types.ts`, `session-upsert-broadcast.service.ts` | Событие содержит одновременно `fullTitle`, `forkedFromSessionId` и `forkAncestors`. |

отдельно от тега; `react-virtuoso`, прямой `zod`, скрипт обновления сохранены.

## Статус выкатки

Доставка кода: merge-коммит → ff-only в `feat/goldjaxe-improvements` →
push `goldjaxe` → `git publish`. Она не является выкаткой.
Владелец отдельно согласовал выкатку 2026-11-16. Перед сборкой сделаны SQLite
backup (проверен `PRAGMA quick_check`), копия `secret.key` и архив прежних
`dist/`/`dist-server/`; все резервы приватные, вне Git.
Каталог этой выкатки: `~/.cloudcli/deployments/v1.37.9-20261116.QZdmA4/`.
Сборка основного каталога выполняется только в этом согласованном окне;
зависимости не переустанавливаются — lockfile изменил только версию пакета.

Рестарт и проверка выполняются отдельным user-systemd процессом, вне cgroup
боевого сервиса: текущая сессия может оборваться. Проверяющий требует новый
MainPID, активную службу, правильный cwd, HTTP 200 и версию `1.37.9` в `/health`,
а также доступность клиента. **Факт успешной выкатки — строка `УСПЕШНО` в
`result.txt` этого каталога**, не наличие сборки или коммита. При ошибке там
записывается причина; автоматического отката БД нет ([деплой](../deploy.md)).

Временный сервер останавливается по проверенным PID/cwd/порту. Оба worktree
удаляются после проверки вхождения их HEAD в целевую ветку и сохранности данных;
тестовые материалы остаются в указанном внешнем каталоге.
