# Файлы вне проекта открываются на чтение

> Разделы реестра §4.5, §15. Часть [реестра правок форка](../fork-changes.md): номер § — постоянный адрес правки, по нему на эту страницу ссылаются код и коммиты.

## §4.5 Картинки из чата открываются как картинки, а не в текстовом редакторе

- **Слой:** frontend + server · **Столкновение:** 🟡 · **PR:** кандидат.
- **Симптом:** клик по ссылке на `.png` в рассуждениях агента открывал панель
  редактора с плашкой «Unable to display this file.» и путём под ней. Текстовые
  файлы при этом открывались нормально.
- **Причина (не та, что кажется):** ветка «файл — изображение → `<img>`» в
  апстриме **уже есть** (`CodeEditor.tsx:198`, `getPreviewKind`), и `.png`
  распознаётся верно. Ломалась **доставка байтов**: превью грузит файл только
  через `/api/file-tree/projects/:id/files/content`, а тот зовёт
  `resolvePathInsideProject` (`file-tree.service.ts:72-83`) → всё вне корня
  проекта отбивается **403 PATH_OUTSIDE_PROJECT**. Скриншоты агента лежат в
  `/tmp/...`, то есть вне любого проекта.
- **Почему «текст работал»:** открывавшиеся текстовые файлы были **внутри**
  проекта. Ограничение общее — `readTextFile` (:353) и `openFile` (:367) зовут
  одну и ту же проверку. Текст из `/tmp` упал бы так же. Дело не в типе файла.
- **Фикс (сервер):** новый роут `GET /api/assets/local-media?path=<abs>` +
  сервис `local-media.service.ts`. Отдаёт файл по абсолютному пути **только**
  если: (1) путь внутри allowlist-каталогов, (2) расширение — медиа, которое
  браузер рендерит сам. Проверено: `/etc/passwd`, обход через `..`, `~/.ssh/*`
  и симлинк из `/tmp` наружу → `forbidden`; `realpath` до проверки границы
  закрывает побег по симлинку. Заголовки как у stored-assets: `nosniff`,
  форс-download для SVG.
- **Allowlist:** по умолчанию `os.tmpdir()`, `~/Downloads`, `~/.cloudcli`.
  Переопределяется `CLOUDCLI_MEDIA_DIRS` (разделитель — как в `PATH`).
- **Фикс (клиент):** (1) `CodeEditorMediaPreview` пробует цепочку источников —
  проектный роут, затем `local-media` для абсолютных путей. (2) Клик по ссылке
  на картинку в чате открывает **lightbox поверх ленты**
  (`FilePathLightbox` → переиспользует апстримовский `ImageLightbox`), а не
  панель редактора: редактор рассчитан на текст и на телефоне занимает весь
  экран. Не-картинки открываются в редакторе как раньше.
- **Файлы:** `server/modules/assets/services/local-media.service.ts` (новый),
  `server/modules/assets/assets.routes.ts`,
  `src/components/chat/view/subcomponents/FilePathLightbox.tsx` (новый),
  `src/components/chat/view/subcomponents/Markdown.tsx`,
  `src/components/code-editor/view/subcomponents/CodeEditorMediaPreview.tsx`.
- **Мерж-заметка:** роут добавлен в конец `assets.routes.ts` (монтируется под
  `authenticateToken`, `server/index.ts:159`) — при обновлении upstream следить
  за этим файлом и за сигнатурой `getPreviewKind`.
- **Мерж-заметка (v1.37.4).** Апстрим (#1347) открыл на чтение `/tmp`,
  `os.tmpdir()` и `~/.claude/projects` через проектный роут
  (`READ_ONLY_ROOTS`, `resolveReadablePath`) — самый частый наш случай
  (скриншоты в `/tmp`) теперь закрывает он, ведь цепочка всегда начинает с
  проектного роута. `local-media` остаётся нужен для `~/Downloads`,
  `~/.cloudcli` и каталогов `CLOUDCLI_MEDIA_DIRS` (на ноуте владельца — весь
  `~/Documents`) и когда нет проекта. Клик по ссылке объединён с апстримовским
  #1256: ссылка на папку (`…/`) открывает дерево файлов, `путь:строка` —
  редактор на нужной строке, картинка — наш лайтбокс. `FilePathLightbox` теперь
  получает `projectId` из апстримовского `MarkdownWorkspaceContext` — раньше
  он его не получал вовсе, и относительная ссылка на картинку проекта не
  открывалась.
- **Дополнение (§15).** Allowlist `local-media` теперь всегда включает и
  `CLOUDCLI_READ_ROOTS` — одна настройка открывает каталог обоим звеньям цепочки.

## §15 Файлы вне проекта открываются на чтение (`CLOUDCLI_READ_ROOTS`)

- **Слой:** server + инфра · **Столкновение:** 🟡 (несколько строк в
  апстримовском `server/shared/utils.ts` и его тесте) + 🟢 (`local-media` — наш
  файл) · **PR:** кандидат — настраиваемые корни на чтение полезны не только
  нам.
- **Симптом (13.10.2026):** ссылка агента на
  `~/.local/share/prorostai-app/…/example-work-1440.png` открывалась плашкой
  «Unable to display this file.», хотя файл на диске есть. То же с любым
  файлом вне проекта и вне `/tmp`: текст — `403 Path must be under project
  root` в редакторе.
- **Причина:** просмотрщик читает вне корня проекта только «корни на чтение»
  апстрима (#1347: `/tmp`, `os.tmpdir()`, `~/.claude/projects` — список
  захардкожен), а запасной `local-media` — только свой allowlist
  (`/tmp`, `~/Downloads`, `~/.cloudcli`, у нас ещё `~/Documents`). Агент же
  пишет куда угодно в домашней папке.
- **Что сделано:**
  - `getExtraReadRoots()` в `server/shared/utils.ts` читает
    `CLOUDCLI_READ_ROOTS` (разделитель как в `PATH`; пустые и относительные
    элементы отбрасываются) и дописывает корни в `READ_ONLY_ROOTS`. Через них
    идут `readTextFile`/`openFile` (редактор и превью медиа) и обзор каталогов
    в дереве файлов.
  - `getAllowedMediaRoots()` в `local-media.service.ts` добавляет те же корни
    к своему allowlist — для ссылок без проекта.
  - Drop-in службы `~/.config/systemd/user/cloudcli-fork.service.d/read-roots.conf`:
    `CLOUDCLI_READ_ROOTS=%h:/tmp:/var/tmp:/dev/shm:/mnt/goldjaxe-files` — ровно
    те места, куда служба может писать. `media-dirs.conf` этим перекрыт, оставлен
    как был.
- **Границы (не ослаблять):** только чтение — запись, переименование, удаление
  и загрузка по-прежнему идут через `resolvePathInsideProject` и вне проекта
  отбиваются. Симлинк из корня наружу не проходит (`realpath` до сравнения),
  `allowed` не совпадает с соседом `allowed-sibling`. Права ОС никто не
  обходит: недоступное пользователю `mx-linux` → 403. Это не новая
  возможность для вошедшего: у него и так есть встроенный терминал и агент с
  полным доступом.
- **Без переменной** поведение как у апстрима — корни не добавляются.
- **Тесты:** `server/shared/tests/extra-read-roots.test.ts` (разбор переменной,
  чтение внутри, соседний каталог, `..`, симлинк наружу),
  `server/modules/assets/tests/local-media.service.test.ts` (корни на чтение
  попадают в allowlist, только медиа, вне корней — 403). В апстримовский
  `read-only-roots.test.ts` добавлен сброс `CLOUDCLI_READ_ROOTS` до импорта:
  сессия из боевой службы наследует переменную, и под ней фикстура теста
  оказалась бы читаемой.
- **Проверки:** typecheck и lint чистые; полный серверный прогон в изолированном
  env — 708/710, падает только `conversation search streams title matches
  before transcript results` (`provider.routes.test.ts`), и он же падает на
  чистом HEAD `02ce32cf` — к этой правке отношения не имеет (причина — нет
  бинарника ripgrep в `node_modules`, [§16.4](merge-v1.37.5.md)).
- **Мерж-заметка:** если апстрим сделает корни на чтение настраиваемыми сам —
  перейти на его механизм, `getExtraReadRoots` снять, drop-in переписать на его
  переменную. Следить, чтобы `READ_ONLY_ROOTS` оставался единственным
  источником для `resolveReadOnlyRootPath`.
