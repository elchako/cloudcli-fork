# Защищённые данные в чате

Часть [реестра правок форка](../fork-changes.md).

## §27. Несколько полей и одноразовая проверка подключения

**Зачем:** пароль и токен не должны быть частью обычного сообщения или доступного
агенту файла. Замок рядом со скрепкой открывает форму ввода, а не общий файловый
загрузчик. Ластик снят с панели; `/clear` оставляет прежнее поведение.

**Слой:** клиент, WebSocket, ран Claude Code, независимый Linux-исполнитель.
**Столкновение с upstream:** 🟡, проверять композер, запуск чата и сборку MCP.
**PR:** не открыт. **Выкатка:** клиент и сервер ревизии `457cf25f` на `:3302`
21.11.2026. Проверены новый PID, `/health`, выдача нового клиента и отказ на
анонимный запрос к `/api/protected-data`. Исполнитель не настроен.

### Пользовательский сценарий

Форма выезжает снизу на телефоне и открывается над замком на компьютере. В шапке — только заголовок и закрытие. Назначение выбирается под полями. «Добавить поле» добавляет пару «Название → Значение» (до 12 пар).
Значения скрыты, модель узнает только названия. Названия используют латиницу,
цифры и подчёркивание (первый символ — буква или `_`, до 32 символов); не
пишите в названии секрет. «Прикрепить к сообщению» закрывает форму и добавляет
плашку над редактором. По плашке можно отредактировать набор, крестик снимает его.
Поля существуют только в памяти вкладки; смена чата, провайдера или перезагрузка
не переносит их в новый черновик.

Обычная стрелка отправляет текст. Например: «Проверь доступ к настроенному API».
Повторного подтверждения нет: разрешён только заранее выбранный администратором
`GET` на точный HTTPS-адрес. Без задания набор не отправляется. Работает только
для нового прямого сообщения в режиме Claude Code, не для очереди, расписания,
steering, `/btw`, замены сообщения или фона. Импорт из `.env`/текста и передача
целых файлов не входят в эту версию.

### Канал и границы

- Нужен доверенный клиент CloudCLI в защищённом контексте браузера (HTTPS или
  localhost). `GET /api/protected-data` по авторизации возвращает профиль:
  несекретное название, имена полей, ревизию, открытый ключ — не адрес назначения.
- Браузер шифрует значения ключом AES-256-GCM, оборачивает ключ RSA-OAEP-SHA256.
  В AAD входят версия, ревизия, ID сеанса, одноразовый nonce, время и названия.
  Отдельный `POST /api/protected-data` получает только конверт. Backend сверяет
  отпечаток публичного ключа, держит конверт в ограниченном реестре в памяти
  и отдаёт случайный ID. В `chat.send` передаётся только этот ID вне `options`.
- Конверт привязан к авторизованному пользователю, сеансу и одному прямому ходу.
  SDK не получает ID, конверт, значения, адрес и пути. Только в этом ходе
  появляется `mcp__cloudcli-protected-data__check_connection`: без аргументов,
  с именами полей и ответом из фиксированного набора статусов. Значения не
  пишутся в историю, чат-черновики, БД, файлы, логи или окружение CLI.
- Только выделенный процесс расшифровывает набор. Он использует либо поле для
  Bearer, либо два поля для Basic. Если приложено настроенное поле `URL`, оно
  должно точно совпасть с адресом из конфига, а не выбирать адрес. Прочие поля
  не используются. Запрос не следует перенаправлениям, не отдаёт тело ответа
  или заголовки. Настроенный сервис **получает** данные для авторизации.
- Срок конверта в актуальной сборке — 30 минут с отправки (§27.2). Сервер принимает один `nonce` только для
  одного хода за срок жизни конверта; исполнитель независимо блокирует повторное
  применение. Новый запуск исполнителя меняет ревизию. Доступ отзывается при
  отмене и при первом завершении хода, даже если SDK продолжает фоновую работу.
  Steering и нативный побочный вопрос не используют этот инструмент. Уже
  начавшийся HTTPS-запрос невозможно отозвать задним числом.
- Не включать, если агент может стать администратором, читать процесс исполнителя,
  управлять браузером с формой или менять раздаваемый клиент CloudCLI. Это не
  защита от заражённого браузера/операционной системы. UID должен отличаться;
  CloudCLI не подключается к сокету своего UID или от root. Сам сокет нужно
  разрешить только серверу CloudCLI и запретить CLI и дочерним инструментам
  средствами ОС: Unix IPC не отличает агента от сервера, если им оставить общие
  права на сокет. Удаление пути из окружения этого не исправляет. Код исполнителя,
  приватный ключ, конфиг, каталог сокета и доверенный клиент устанавливает оператор
  вне доступной агенту записи. Шифрование в чате не делает скрытыми данные,
  которые пользователь параллельно вставил в обычное сообщение или оставил в проекте.

### Отдельная настройка администратором (Linux)

В Git нет ключей, конкретных адресов или включённого юнита. Подготовить отдельного
системного пользователя `cloudcli-executor` без входа и группу `cloudcli-protected`.
Пользователю CloudCLI нужен доступ к сокету через эту группу, но не запись в его
каталог. Операции ниже — вне управляемой агентом среды.

1. Из проверенной сборки установить `executor-main.js`, `executor.js`,
   `protocol.js`, `project-env.js`, `env-file-writer.js`, `apply-receiver.js` из `dist-server/server/modules/protected-data/` в отдельный
   каталог, например `/opt/cloudcli-executor/`, недоступный агенту на запись.
   Добавить рядом `package.json` с `{"type":"module"}`. Node.js ≥ 22;
   приложение и его `node_modules` исполнителю не нужны.
2. Сгенерировать отдельный RSA-ключ, например `openssl genpkey -algorithm RSA
   -pkeyopt rsa_keygen_bits:3072 -out /etc/cloudcli-executor/private.pem` с
   `umask 077`. Владелец ключа и конфига — `cloudcli-executor`, режим `0600`;
   оба файла в закрытом каталоге. Сверить PIN командой `openssl pkey -in
   /etc/cloudcli-executor/private.pem -pubout -outform DER | sha256sum`.
3. Пример `config.json`: адрес условный, заменить на свой безопасный `GET` без
   побочных эффектов. Для Basic вместо `auth` использовать
   `{"type":"basic","loginField":"LOGIN","passwordField":"PASSWORD"}`.

```json
{
  "socketPath": "/run/cloudcli-executor/executor.sock",
  "privateKeyPath": "/etc/cloudcli-executor/private.pem",
  "target": "https://api.example.com/v1/me",
  "label": "Проверка доступа к API",
  "auth": { "type": "bearer", "tokenField": "TOKEN" },
  "urlField": "URL"
}
```

4. Пример отдельной службы. Код и конфигурация не читаются из worktree.

```ini
[Unit]
Description=CloudCLI — изолированный исполнитель защищённых данных
After=network.target

[Service]
User=cloudcli-executor
Group=cloudcli-protected
RuntimeDirectory=cloudcli-executor
RuntimeDirectoryMode=0750
Environment=CLOUDCLI_PROTECTED_DATA_EXECUTOR_CONFIG=/etc/cloudcli-executor/config.json
ExecStart=/usr/bin/node /opt/cloudcli-executor/executor-main.js
NoNewPrivileges=yes
ProtectSystem=strict
ProtectHome=yes
PrivateTmp=yes
LimitCORE=0
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

5. В настройках службы CloudCLI добавить `SupplementaryGroups=cloudcli-protected`,
   `CLOUDCLI_PROTECTED_DATA_SOCKET=/run/cloudcli-executor/executor.sock` и
   `CLOUDCLI_PROTECTED_DATA_KEY_SHA256=<hex отпечаток DER>` как переменные
   окружения. Перед включением проверить изоляцию, права сервера и доверенность
   раздаваемого UI, затем перезапуск по отдельному согласованию. Без действующего
   профиля CloudCLI не предлагает вводить значения.

### Проверка

Сборка, typecheck и lint — в отдельном рабочем дереве. Профильные серверные и
клиентские тесты покрывают сверку PIN, срок и повтор конверта, отзыв, отправку
только в исходный ход, ошибку и смену сеанса. В собранном CloudCLI проверены
Chrome 390×844 с касаниями и настольный тёмный режим: форма, плашка, отправка
шифртекста в HTTP и только ID в WebSocket. Профиль и значения синтетические,
модель и боевой API не вызывались; на физическом телефоне не проверялось.

### Ключевые файлы

- `src/modules/chat/protected-data/`, `hooks/useProtectedDataComposer.ts` и
  `hooks/useChatComposerState.ts` — форма, WebCrypto, scoped-набор и отправка.
- `server/modules/protected-data/` — маршруты, реестр конвертов, протокол,
  инструмент и выделенный исполнитель.
- `server/modules/websocket/services/chat-websocket.service.ts` и
  `server/modules/providers/list/claude/claude-runtime.provider.ts` — привязка
  к рантайму и закрытие доступа после хода.

## §27.1. Локальная проверка доставки без API

**Риск слияния:** 🟢. **PR:** не открыт. **Выкатка:** не выполнена. Цель —
проверить работу защищённой передачи без выбора сервиса и ввода API-ключа.

В приватном конфиге исполнителя вместе с `socketPath`, `privateKeyPath` и
несекретным `label` задаётся `"operation": "local-check"`. При этой операции
`target`, `auth` и `urlField` запрещены. В форме виден режим «Проверка доставки ·
без сети», у набора нет обязательных имён API. Исполнитель проверяет конверт и
возвращает `received` один раз; значение не применяется и не пересылается.
Дополнительные сетевые проверки по-прежнему требуют отдельного согласованного
профиля с фиксированным адресом.

Отдельную службу для локального режима можно запустить до переключения
CloudCLI. Для неё `PrivateNetwork=yes` и `RestrictAddressFamilies=AF_UNIX`;
сокет доступен только веб-службе по группе `cloudcli-protected`. Системный
`node` и код службы должны быть в каталоге, которым не может управлять агент.
Закрытый ключ перечитывать в рабочую сессию не нужно: для привязки используется
только отпечаток открытого ключа. Подключать сокет к `:3302` можно только после
проверки доверенного интерфейса, запрета доступа агента к сокету и HTTPS.

## §27.2. Встроенный локальный режим и срок 30 минут

**Риск слияния:** 🟢. **PR:** не открыт. **Выкатка `:3302`:** 22.11.2026.
Проверены новый PID, `/health`, выдача клиента и авторизованный профиль локального режима.
По согласованию нужен запрет передачи значений в модель штатным каналом,
а не защита от произвольного кода на самом ноутбуке. Для этого добавлен
`CLOUDCLI_PROTECTED_DATA_MODE=memory` в пользовательской службе CloudCLI.
Режим по умолчанию не меняется. Сокет, закреплённый PIN и установленные ключи
отдельной службы в режиме `memory` не используются.

Встроенный исполнитель создаёт ключ в памяти. В версии §27.2 без получателя
была только операция `local-check` (актуальный выбор — §27.4): распаковывает и проверяет набор
локально, ничего не отправляет в сеть и возвращает только `received`. Адрес или способ передачи агент выбрать
не может. Это проверка доставки, не выполнение произвольной команды с секретами.
Код отправки сообщения и инструмента по-прежнему видит только метки и статус;
ни конверт, ни значения не входят в SDK или историю. Браузер шифрует набор
как раньше: нужен доступный Web Crypto, обхода на передачу значений открытым
текстом нет. Менять HTTPS или Tailscale специально для выкатки не требуется.

Набор принимается на один ход **до 30 минут с отправки**, при применении,
остановке или окончании хода доступ исчезает раньше. После истечения конверт
недоступен, после перезапуска ключ и все прежние конверты недействительны.
При проверке доставки данные на диск не пишутся. Отдельную службу такой drop-in не обновляет;
при её использовании следует устанавливать совместимую сборку исполнителя.

Для отзыва режима убрать drop-in `protected-data-memory.conf` и выполнить
`systemctl --user daemon-reload` и рестарт. Режим не защищает от кода, который
может подменить браузерный интерфейс или читать память CloudCLI на хосте.

## §27.3. Применение поля у закреплённого получателя

**Риск слияния:** 🟡. **PR:** не открыт. **Выкатка:** ревизия `27a35be0` на `:3302` 22.11.2026; подтверждены перезапуск, `/health` и выдача нового клиента.
Проверка доставки сама по себе не применяет значения. Во встроенном режиме
можно зарегистрировать одного получателя через абсолютный путь
`CLOUDCLI_PROTECTED_DATA_APPLY_CONFIG` к JSON-файлу владельца CloudCLI с режимом
`0600`. В версии §27.3 без файла настройки оставалась локальная проверка; актуальные варианты — в §27.4. Пример для существующего
доверенного systemd `EnvironmentFile` (пути здесь условные):

```json
{
  "label": "Локальная служба · SERVICE_API_KEY",
  "field": "TOKEN",
  "executable": "/opt/cloudcli-tools/node",
  "args": [
    "/opt/cloudcli-tools/env-file-writer-main.js",
    "/var/lib/example-service/service.env",
    "SERVICE_API_KEY"
  ]
}
```

Форма показывает метку назначения и имя обязательного поля до отправки.
Модель получает инструмент `apply_protected_field` без параметров. Имя поля,
исполняемый файл и его аргументы задаёт только конфигурация получателя, не
сообщение и не инструменты модели. Срок 30 минут и один ход сохраняются.

Исполнитель запускает закреплённый процесс **без shell**, передаёт только
выбранное значение в `stdin` и не читает stdout/stderr. Значение не помещается
в argv или окружение. Приёмник сообщает результат кодом завершения; при
сбое или истечении тайм-аута повтор автоматически не выполняется. Общие
ограничения файловых инструментов остаются прежними.

`env-file-writer-main.js` — приёмник из `dist-server/server/modules/protected-data/`
(рядом нужны `env-file-writer.js`, `protocol.js` и ESM-окружение). Он обновляет
одну переменную в плоском `EnvironmentFile`: требует существующий файл
`0600`/`0640` владельца процесса, отвергает ссылки и неоднозначный синтаксис,
сохраняет режим, UID, GID и остальные строки. Подмена файла выполняется
атомарно. Процесс не повышает права и не запускает службу после записи.
После применения промежуточный набор недоступен; на целевом диске значение
остаётся, как и положено при записи конфигурации.

Для файла на другом сервере нужен отдельно закреплённый, доверенный приёмник
с доступом только к согласованному назначению. Например, проверенный
оператором обёрточный процесс может передать `stdin` по SSH с фиксированным
хостом и проверкой ключа хоста. CloudCLI сам не выбирает адрес, не настроен
на какой-либо сервер этим изменением и не передаёт значение в командную
строку SSH. Если после записи агенту выданы права чтения этого файла, режим
не гарантирует изоляцию от такого чтения: штатная операция возвращает только
статус, проверять её чтением секрета не нужно.

## §27.4. Назначение на одно сообщение, произвольные имена полей

**Зачем:** одним замком в разных чатах применять разные переменные. В шапке
остался только заголовок. Пользователь выбирает назначение **под полями**;
отправка текста или имя переменной не могут подменить выбор. **Слияние:** 🟡
(композер чата и выдача одноразового инструмента). **PR:** не открыт.

Во встроенном режиме без конфига есть два выбора: только проверка доставки или
`.env` текущего проекта. Для записи нужен **уже существующий** плоский `.env`
в корне Git-проекта чата, исключённый из Git, с режимом `0600` или `0640`.
Каталог файла должен принадлежать пользователю службы или root, без записи для группы
и остальных. Корень приходит из серверной строки сеанса, не от агента. Ссылки, отслеживаемые
файлы, неоднозначный синтаксис и значения с управляющими символами, двойной
кавычкой, обратной косой чертой, обратной кавычкой или `$` для `.env` отклоняются.
Весь набор записывается атомарно. Запись оставляет значения на диске;
если агент может читать файл, это **не** изоляция от последующего чтения.
Локальный `.env` не означает доставку на VPS или перезапуск службы.

Для других назначений тот же `CLOUDCLI_PROTECTED_DATA_APPLY_CONFIG` принимает
каталог вместо одиночной привязки §27.3. Пример (пути условные):

```json
{"targets":[{"id":"service-env","label":"Служба · файл окружения",
 "executable":"/opt/cloudcli-tools/node","args":["/opt/cloudcli-tools/env-file-writer-main.js","/var/lib/example/service.env"]}]}
```

Каталог заменяет встроенные назначения; от 1 до 16 закреплённых процессов.
Каждый получает JSON-массив пар `[имя, значение]` через stdin. Имена переменных
не нужно перечислять в конфиге. Добавление нового **доверенного места** требует
регистрации и перезапуска; смена чата, названия поля или значения — нет. Внешние
получатели общие для инстанса: публикуйте только те, куда всем его пользователям
разрешена запись. Код и конфигурация обработчика — вне записи агента.

Для VPS: на удалённой стороне отдельный непривилегированный пользователь с правом
записи в конкретный `EnvironmentFile`. Для его отдельного SSH-ключа ограничьте
`authorized_keys` через `restrict,command="/opt/cloudcli-tools/node /opt/cloudcli-tools/env-file-writer-main.js /var/lib/example/service.env"`.
На стороне CloudCLI назначение — `/usr/bin/ssh` с **фиксированными** хостом,
пользователем, ключом и проверенным `known_hosts` (`BatchMode=yes`,
`IdentitiesOnly=yes`, `StrictHostKeyChecking=yes`, `ClearAllForwardings=yes`,
`-T`). Не используйте административный ключ или отключение проверки хоста.
Приёмнику нужны `env-file-writer-main.js`, `env-file-writer.js`, `protocol.js` и
ESM-окружение. SSH, файл назначения и службу выбирает владелец, а не модель.

Ключевые файлы: `ProtectedDataForm.tsx`, `protected-data-client.ts`,
`protocol.ts`, `relay.ts`, `executor.ts`, `project-env.ts`, `env-file-writer.ts`.
`target` входит в AES-GCM AAD; подмена назначения делает конверт непригодным.
Старые формы конвертов для прежних режимов сохраняют прежний AAD. Проверено на
синтетических полях двух чатов через настоящий MCP-вызов; отдельно — SSH с
проверкой ключа хоста и принудительной командой на изолированном loopback-сервере.
