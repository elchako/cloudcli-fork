# Раздача форка команде

> Раздел реестра §11. Часть [реестра правок форка](../fork-changes.md): номер § — постоянный адрес правки, по нему на эту страницу ссылаются код и коммиты.

## §11 Раздача форка команде: GitHub-зеркало + скрипт обновления

- **Слой:** инфраструктура · **Столкновение:** 🟢 (новые файлы) · **PR:** нет
  (специфика холдинга, апстриму не нужно).
- **Зачем:** форком пользуется не только Артём. Раньше коллегам уходил
  zip-архив — без истории, без внятного способа обновиться. Теперь у них
  нормальный git-репозиторий и обновление одной командой.
- **Схема зеркала:** внутренний git холдинга (`goldjaxe`,
  `git.q-standard.com`) остаётся **основным** — разработка идёт там, в ветке
  `feat/goldjaxe-improvements`. GitHub `elchako/cloudcli-fork` (приватный) —
  **зеркало только на чтение** для команды, ветка `main`:

  ```
  Артём → goldjaxe/feat/goldjaxe-improvements   (основной, сюда коммиты)
            ↓ git push github …:main
          github/main                            (зеркало, отсюда тянет команда)
  ```

  Публикация новой версии:
  `git push github feat/goldjaxe-improvements:main`.
  Есть алиас: `git publish` (см. ниже).
- **Почему зеркало односторонне:** команда в GitHub не пушит. Если кто-то
  закоммитит туда, ветки разойдутся и `update.sh` остановится на
  `merge --ff-only`, а не устроит молчаливый merge-коммит.
- **Скрипт обновления:** `scripts/update.sh` — fetch → показ новых коммитов →
  `merge --ff-only` → `npm install --include=dev` → `npm run build` →
  перезапуск службы. Режимы `--check` (только посмотреть) и `--no-restart`.
  Обёртка: `npm run update`.
- **Системы у всех разные,** поэтому способ перезапуска не захардкожен:
  автоопределение (systemd user-scope → pm2 → launchd), поверх — локальный
  конфиг `scripts/update.local.conf` (в `.gitignore`, у каждой машины свой) с
  `CLOUDCLI_SERVICE` / `CLOUDCLI_SERVICE_SCOPE` / `CLOUDCLI_LAUNCHD_LABEL` /
  `CLOUDCLI_RESTART_CMD`. Не нашлось способа — скрипт не угадывает, а
  печатает подсказку и выходит с ошибкой; код при этом уже собран.
- **Защиты в скрипте:** отказ при незакоммиченных правках (иначе `merge` их
  затрёт), проверка Node ≥ 22, отказ на detached HEAD, `--include=dev` при
  установке (при `NODE_ENV=production` npm иначе пропустит devDependencies и
  сборка упадёт на `vite: not found`).
- **Файлы:** `scripts/update.sh`, `scripts/update.local.conf.example`,
  `docs/ru/install.md` (установка с нуля + обновление + типовые проблемы),
  `.gitignore` (+`scripts/update.local.conf`), `package.json`
  (+скрипт `update`).
- **Риск при мерже:** 🟢 — всё новое и своё. Единственная общая точка —
  `package.json` (секция `scripts`) и `.gitignore`; конфликт, если возникнет,
  разрешается тривиально (обе стороны дописывают строки).
- **Что проверить перед раздачей людям:** репозиторий на GitHub приватный;
  в истории нет секретов (`.env`, `*.db` — в `.gitignore` с самого начала);
  из чувствительного в доках только Tailscale-IP `100.64.0.27` (CGNAT,
  доступен лишь внутри tailnet).
