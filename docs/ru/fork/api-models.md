# Модели подключённого API

> Разделы реестра §22, §22.1. Часть [реестра правок форка](../fork-changes.md).

## Пользователю

Когда у Claude Code настроен API/шлюз, список моделей берётся с него, а не
ограничивается вшитым набором CloudCLI. Новую модель не нужно добавлять в код:
она появится при следующем чтении каталога. Название берётся из
`display_name`/`name`; если его нет — используется ID или подпись из известных
метаданных. Сами ID не переписываются и не получают автоматически `[1m]`.

Открыть библиотеку: карточка выбора модели в новом чате → «Добавить модель»
(`Add model`). В разделе «Модели подключённого API» есть кнопка обновления с
круговой стрелкой. Она запрашивает свежий список сразу, не дожидаясь TTL.
Обновившийся список доступен и обычному выбору модели. Штатный вариант SDK
`default` оставлен отдельно: первая модель из API не становится выбором
пользователя автоматически.

Ручные записи из библиотеки остаются. Если API начинает возвращать тот же ID,
ручное имя и effort имеют приоритет. Удаление ручного описания не переводит
сеансы на другую модель, если этот ID остаётся в API. Режим «Только мои модели»
сохраняет прежний смысл и скрывает также остальные модели API — выключите его,
если нужен полный список.

Старые сеансы не мигрируют на другие ID. Фактическую доступность и поддержку
чата/инструментов определяет сам API: его каталог может содержать также
графические и служебные модели, которые не подходят для обычного агентного
диалога. Обнаружение модели не обещает совместимость всех её возможностей.

## §22 Устройство и границы

- **Слой:** server + frontend · **Столкновение:** 🟡 (локальная интеграция в
  каталог, runtime и библиотеку моделей) · **PR:** кандидат, не открыт.
- Адаптер Claude читает `GET /v1/models` без запуска CLI и создания служебной
  сессии. Статический `CLAUDE_PREDEFINED_MODELS` остался запасным каталогом и
  метаданными известных моделей; он больше не ограничивает обнаружение.
- Credentials берутся существующим `resolveSmallModelCredentials`: окружение
  процесса, затем `~/.claude/settings.json`. Подписочный OAuth не используется
  как прямой API-ключ. Ничего не переносится в `user_settings`/новую таблицу и
  не отправляется браузеру; API-ключи не логируются.
- **CLIProxyAPI:** `anthropic-version` включает маски `claude-fable-5-dd-*`
  даже с Bearer. Поэтому каталог шлюза сначала запрашивается через Bearer без
  этого заголовка — возвращаются обычные ID. При 400/401/403/404 выполняется
  совместимый повтор с исходным Anthropic-протоколом в тот же endpoint.
  Официальный `api.anthropic.com` сразу получает свой протокол; 429/5xx не
  вызывают дополнительный запрос. Сводка вслух сохраняет прежний протокол.
- Один таймаут 3 секунды ограничивает все страницы. Используются `has_more`,
  `last_id`/`after_id`, максимум 10 страниц; повтор курсора или ошибка не дают
  усечённый список. Редиректы запрещены, ссылки `next` из ответа не используются.
- Кэш — 5 минут, одновременные запросы объединены. Просроченный успешный список
  возвращается немедленно с фоновым обновлением. После сбоя — пауза 30 секунд,
  последний успешный список сохраняется. Endpoint, тип авторизации и отпечаток
  ключа входят в ключ кэша; ответ старого подключения не загрязняет новое.
- `SOURCE` в ответе: `api` — успешный каталог; `api-cache` — сохранённый каталог;
  `fallback` — API недоступен/ответ не годится, показан запасной набор. Без
  прямых API credentials остаётся прежнее поведение без поля `SOURCE`.
- Известные effort сохраняются, неизвестным моделям уровни не выдумываются.
  Совместимость с масками CLIProxyAPI остаётся для метаданных, GPT-суффикса и
  сопоставления `modelUsage`. Исходный ID выбора не декодируется перед SDK.
  `CLAUDE_CODE_MAX_CONTEXT_TOKENS=930000` и прежние ID сеансов не менялись.
- Источник и кэш не вмешиваются в `user_preferences`/`userSettingsSync`.
  Остальные провайдеры продолжают использовать собственные штатные каталоги.

## §22.1 Группировка по провайдеру API, а не по названию модели

- **Слой:** server + frontend · **Столкновение:** 🟡 (общие типы, mapper,
  объединение каталогов и меню) · **PR:** не открыт.
- **Что и зачем:** у Antigravity доступны модели Gemini и Claude. Поэтому
  `gpt-*`/`gemini-*`/`claude-*` не определяют группу. Используется `owned_by`,
  которое шлюз уже возвращает в обычном `GET /v1/models`; шлюз не менялся.
  Метка не обещает конкретный аккаунт или фактический backend каждого запроса.
- Транспорт сохраняет непустую строку `owned_by` до 128 символов как
  `catalogProvider`; нестроковые/пустые/слишком длинные значения игнорируются.
  Поле проходит через кэш и mapper без изменения ID. Ручное описание того же
  ID наследует группу из актуального API, включая «Только мои модели»;
  имя и effort остаются ручными. Группа не сохраняется в БД и не устаревает
  при смене подключения.
- Общая утилита `groupModelsByCatalogProvider` группирует нижнее меню, общий
  выбор и библиотеку. Порядок групп — первое появление в API, порядок моделей
  внутри группы сохранён. Новое `owned_by` создаёт группу автоматически.
  Штатный `default` и записи без провайдера выделены отдельно; если метаданных
  нет вообще, остаётся прежний плоский список без угадывания бренда.
- `owned_by` не описывает reasoning-capabilities и не даёт оснований добавлять
  уровни effort. Обычный API этого инстанса их не сообщает; Codex-client форма
  каталога может содержать шаблонные уровни даже у генераторов изображений.
  Эти поля не используются как источник достоверных возможностей модели.
- `LLMProvider` остаётся CLI-интеграцией: выбор модели Antigravity в каталоге
  Claude Code не переключает runtime на другой CLI. Поиск в общем выборе
  учитывает имя группы и раскрывает совпадения. Вместо неверного логотипа
  Anthropic у API-групп показывается нейтральный значок.
- **Файлы:** `server/shared/{small-model,types}.ts`,
  `server/modules/providers/{list/claude/claude-models.provider,services/provider-models.service}.ts`,
  `src/shared/{types,modelProviderGroups}.ts`,
  `src/modules/chat/{composer/{ComposerModelMenu,ModelGroupList},modals/ModelLibraryPanel,transcript/ProviderSelectionEmptyState}.tsx`.
  Локали EN/RU; устранён дублирующий раздел `composer` в RU, чтобы `Авто`
  действительно загружалось из перевода.
- **Проверка:** 33 профильных клиентских теста и 55 серверных тестов успешны.
  В браузере — 12 сочетаний 320/390/1024px, RU/EN, светлой/тёмной темы;
  тач-выбор в обоих меню, поиск Antigravity и группы библиотеки. Имена и ID
  сохраняются, новый провайдер появляется без правки кода, переполнения страницы
  и ошибок JavaScript нет; все API-запросы модельного стенда — только каталог,
  генераций 0. Рабочий шлюз прочитан только обычным GET без изменений.
- **При слиянии:** не смешивать `catalogProvider` с типом `LLMProvider` и
  не восстанавливать группировку по префиксу имени. Контракт расширен только
  необязательным полем, старые каталоги работают без него.

## Контракт и файлы

`GET /api/providers/claude/models` возвращает прежние `OPTIONS`, `DEFAULT`,
`EFFORT_LEVELS`, `CUSTOM_MODELS_ONLY` плюс необязательный `SOURCE`.
`GET /api/providers/claude/models?refresh=1` обходит TTL. Интерфейс
`IProviderModels` не изменён. Библиотека обновляет только нужного провайдера;
поздний первоначальный ответ не затирает ручное обновление, ошибки не очищают
текущий список и выбранную модель.

- `server/shared/small-model.ts` — общий транспорт каталога, пагинация и протокол.
- `server/modules/providers/list/claude/claude-api-models.ts` — кэш и граница credentials.
- `server/modules/providers/list/claude/claude-models.provider.ts` — варианты API + SDK default.
- `server/modules/providers/list/claude/claude-runtime.provider.ts` — совместимость effort/контекста.
- `server/modules/providers/{provider.routes.ts,services/provider-models.service.ts}` — обновление и ручные модели.
- `src/modules/chat/{hooks/useChatProviderState.ts,modals/ModelLibraryPanel.tsx}` — библиотека и обновление.
- `src/shared/{api.ts,types.ts}`, `server/shared/types.ts`, локали EN/RU — контракт и подписи.

## Проверки

- 23 профильных теста транспорта/кэша: неизвестные ID, имена и дубликаты,
  пагинация, протоколы, таймауты, single-flight, TTL, сбои, ротация ключа,
  отсутствие credentials в ответе и совместимость GPT-маски.
- Регрессии общего сервиса: приоритет ручных данных, режим «Только мои»,
  удаление ручного описания с сохранением ID API. Runtime-проверки сохраняют
  effort max и 930k для старого прямого и маскированного GPT ID; отдельно
  проверено сопоставление окна с `modelUsage`, где есть ещё и малая модель.
- Профильные клиентские тесты: обновление одного провайдера, гонка
  первоначального ответа, сохранность выбора при ошибке и холодном fallback,
  отсутствие ложного ограничения при пустом «Только мои», состояние библиотеки.
- Реальный API инстанса прочитан новым кодом: 22 модели + штатный SDK default;
  env/credentials диагностической сессии сверены с процессом службы без вывода
  секретов. Это только GET каталога, не платный запрос к модели.
- Chrome/Playwright 390×844 touch и 1280×800: выбран неизвестный ID, в API
  добавлена модель, кнопка обновления действительно сделала новый запрос и
  новая модель выбрана без замены ID. Горизонтального overflow и ошибок страницы
  нет; счётчик модельных запросов стенда — 0. Скриншоты просмотрены.
- Итоговый полный прогон: 1250 клиентских тестов успешно; 1177 серверных,
  из них 1176 успешно и 1 пропуск. Typecheck/lint — 0 ошибок, 146 прежних
  lint-предупреждений без новых; полная сборка успешна (35 прежних предупреждений
  CSS-минификации).
- Сценарии живого ответа/инструментов для всех обнаруженных моделей не запускались.
