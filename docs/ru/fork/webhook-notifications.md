# Webhook-уведомления и ключ подписи

> Раздел реестра §20. Часть [реестра правок форка](../fork-changes.md).

## Возможность upstream

В настройках уведомлений можно включить один webhook на пользователя. Без
настроенного канала обновление ничего не отправляет. События: `run.completed`,
`run.failed`, `run.cancelled`, `run.background_completed`; отдельная кнопка
проверки отправляет `webhook.test`. В JSON нет текста запроса, ответа и ошибки
модели; есть версия, id события, время, провайдер, id сеанса и исход.

По умолчанию нужен HTTPS; HTTP разрешается явно. Локальные/LAN-адреса допустимы,
но metadata/link-local, unspecified, multicast и зарезервированные адреса
блокируются, DNS проверяется при соединении. Редиректы не выполняются. Не
включать канал и не отправлять проверочное событие на чужой адрес без согласия
владельца: это исходящая передача данных.

## §20 Ключ подписи через sealSecret

- **Слой:** server · **Столкновение:** 🟡 (два локальных изменения чтения/записи
  в upstream-сервисе) · **PR:** не открыт; использует наш общий `secret-box`.
- Upstream хранит ключ подписи в `notification_channel_endpoints.metadata_json`.
  В форке поле `secret` содержит только конверт AES-256-GCM (`gcm.v1.…`),
  созданный `sealSecret`. Расшифрование — только на сервере для подписи.
- Контракт не меняется: `POST /api/notifications/webhook/secret` показывает новый
  ключ один раз; остальные ответы дают только `hasSecret`, а общий endpoint
  уведомлений удаляет `secret` из метаданных ответа. Формат подписи Standard
  Webhooks v1 остаётся прежним.
- Старая открытая запись upstream читается для совместимости и шифруется при
  ближайшем сохранении. Нечитаемый/повреждённый конверт вызывает
  `WEBHOOK_SECRET_UNREADABLE`: отправка не становится молча неподписанной.
  Восстановите исходный мастер-ключ либо удалите и заново настройте канал.
- Мастер-ключ берётся из `CLOUDCLI_SECRET_KEY` или `secret.key` рядом с БД.
  Переносить/резервировать их нужно вместе; это защита отдельного файла БД,
  не скомпрометированного хоста. Все `user_credentials` этим не шифруются.
- **Файлы:** `server/modules/notifications/services/webhook-notifications.service.ts`,
  `server/modules/notifications/tests/webhook-notifications.service.test.ts`;
  общий механизм — `server/shared/secret-box.ts`.
- **Проверки:** ciphertext вместо открытого ключа, перечитывание после сброса
  кэша ключа, подпись исходных байтов независимым signer, удаление ключа,
  перенос открытой записи и запрет отправки при повреждении. Все 24 теста
  webhook-сервиса и маршрутов проходят.

## Маршруты

Все требуют обычную авторизацию CloudCLI:

| Метод | Путь | Действие |
|---|---|---|
| GET / PUT / DELETE | `/api/notifications/webhook` | Прочитать / сохранить / удалить канал |
| POST / DELETE | `/api/notifications/webhook/secret` | Создать или сменить / удалить ключ подписи |
| POST | `/api/notifications/webhook/test` | Одно проверочное событие, даже если канал отключён |
