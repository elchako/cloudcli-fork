## §16.4 На заметку

- **ripgrep не установлен в боевой папке.** В
  `node_modules/@vscode/ripgrep/` нет `bin/rg` (установка от 19.08, postinstall
  тихо не скачал бинарник; `npm install` при неизменной версии пакета его не
  перезапускает). Из-за этого поиск по тексту разговоров на :3302 падает:
  журнал службы 15.10.2026 — `Error searching conversations: spawn …/rg
  ENOENT`. Лечится без пересборки и рестарта: `node
  node_modules/@vscode/ripgrep/lib/postinstall.js` в основной папке (берёт
  кэш `/tmp/vscode-ripgrep-cache-*` или качает с GitHub). Перед выкаткой и в
  `update.sh` стоит проверять наличие `bin/rg`. **Исправлено владельцем
  17.10.2026** перед выкаткой 1.37.5; у коллег проверять отдельно.
- **Имя сеанса со вставкой** — в списке сеансов и в шапке (без ИИ-заголовка)
  видны сырые теги `<pasted_content id=…>`: апстрим разворачивает их только в
  ленте. Наш `extractFirstUserPrompt` пропускает сообщение, начинающееся с
  `<`, то есть сеанс, открытый вставкой, получит ИИ-заголовок по следующему
  сообщению. Актуально с Claude CLI 2.1.282+ (у нас 2.1.280); кандидат в
  доработку — разворачивать вставку и в источнике заголовка.
- **«Только мои модели»** (#1561) — флаг общий на инстанс (`app_config`), не
  per-user. Включение у Claude скроет встроенный каталог (§1) и оставит только
  библиотеку ([§1.5](custom-models.md)).
- **Выкатка — 2026-10-17, по команде владельца.** Перемотка
  `feat/goldjaxe-improvements` на слияние (резерв — ветка
  `backup/pre-v1.37.5-merge`). `npm install` не понадобился: зависимости не
  менялись. Прежняя сборка сохранена в `~/.cloudcli/deploy-backup-v1.37.5`,
  новая собрана `npm run build` в основной папке; служба при сборке не
  перезапустилась. Перед рестартом новая сборка поднята на порту 3398 на
  снимке боевой БД (`sqlite3 .backup`). Схема и миграции применились, сервер
  стартовал без ошибок. Авторизация с настоящим секретом прошла, отдано 364
  проекта, каталог Claude — 11 моделей (обе GPT, две из библиотеки), флаг
  «только мои модели» выключен.
- **Рестарт и публикация — одним отдельным юнитом** (`systemd-run`,
  сценарий и лог — `~/.cloudcli/deploy-v1.37.5.{sh,log}`). Юнит ждёт затишья
  во всех чатах (2 минуты без записи в транскрипты, максимум 30 минут) и
  перезапускает службу. Затем проверяет здоровье: служба активна, `/`
  отвечает, в сборке есть правка [§16.2](gpt-gateway.md). Только после этого он пушит ветку в
  GitLab (`goldjaxe`) и в зеркало GitHub (`git publish`, перемотка вперёд без
  force) и удаляет эталонный worktree. Если служба не поднялась, юнит
  возвращает прежнюю сборку из бэкапа и ничего не публикует. Итог — в логе.
